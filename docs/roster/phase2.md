設計の正は `forms_kintone_phase2_design_20261109.md` と、その業務ルールを置き換える `claude_code_forms_kintone_phase2_handoff_20261109.md`（どちらも 2026-11-09）。ここには実装済みの範囲と、次に必要な作業を記録する。

## このPRの範囲（設計書 §7 の「最初のPR」）

**役員入力・提出原本の版管理・ID22/ID21 の比較・反映計画のプレビュー**までを実装した。
**ID22・ID21 へは一切書き込まない。** accept しても反映されるのは第1段階と同じ ID20 だけで、画面にもそう表示する。

| 項目 | 内容 |
| --- | --- |
| フォーム設定 | 名簿フォームに「役員情報を受け付ける」（`roster_officer_sync`）を追加。既定はオフ。フォームを複製するとオフに戻る |
| 役員枠 | 代表者・副代表者1・会計長は必須。副代表者2・副会計長・総務は「空席」にできる。空の枠は空席を表し、確定すれば既存の担当者の解除になる |
| 団体の入力 | 同じ提出内の入部・在籍の部員から選ぶ（名簿の役職では絞らない）。異なる役職の兼務は同じ人を選ぶ。枠が1つの役職で名簿のその役職の部員が1人なら初期候補にする |
| 人物の申告 | 枠に入れた人ごとに、姓・名・本人の大学メール・所属・学生区分・執行・議会組織への所属を入力する。兼務でも1人分 |
| 主役職 | ID20 の役職は単一選択なので、担当する役職から選んだ主役職を名簿に保存する。枠に入れると自動でそろえ、兼務なら入力欄で選ぶ。マネージャーは名簿側の役職のためそのまま |
| 提出時の検証 | 入部・在籍が重複なく5人以上、必須3役職、候補の在籍状態、同じ役職の番号違いへの重複、主役職、人物の申告（不足・形式・選択肢・名簿の氏名との一致・役員どうしのメール重複）はエラー。定員超過は役職と人数を警告で示し、切り捨てない |
| 提出原本の版 | 対象フォームの提出だけ `payload_version: 2` とし、`rows` は ID20 の形式のまま `officers` を別キーに置く。枠は学籍番号で持つので、行の並べ替えで変わらない。ハッシュは役員情報を含めてキー順を固定して計算する。対象外フォームと旧版は第1段階と同じ形・同じハッシュで、全枠空席には変換しない |
| ID22 の照合 | 学籍番号の完全一致で「既存参照／新規登録／情報不足／競合」を判定する。複数件、氏名の実質的な不一致（空白のみ正規化）、別の学籍番号とのメール重複、対象外の区分は競合として役員反映を保留する。メール・所属などの差は差分に出すだけで、既存人物は上書きしない |
| ID21 の比較 | 団体ごとに現行1件。0件→新規作成、1件→更新、複数件・団体キー不一致→停止。枠ごとに「維持／新しく設定／交代／解除／空席のまま」を表示する。同じ役職内の番号の入替えは変更とせず、既存の枠位置を再利用する（必須の枠は空けない） |
| 登録日 | 「変更時はaccept日を使用」と表示する。役職種別ごとの担当者の集合で比較し、初回・就任・交代・解除・兼務の増減は accept 日、同じ構成や氏名・メールの訂正だけなら既存の日付を維持する。日付の確定は次のPR |
| 計画の指紋 | 案件・提出ハッシュ・アプリID・各比較元のレコードID／リビジョン・操作・登録日の扱いから計算する。比較元が変わると値が変わる（次のPRで accept 時の照合に使う） |
| 担当者画面 | 提出詳細に比較結果を表示する。登録者の属性は operator 以上にだけ表示し、viewer には判定結果だけを表示する。公開フォームには ID22 の内容を返さない |
| 接続確認 | 「反映・接続の確認」で ID22・ID21 の接続と型・選択肢・一意制約・ルックアップを検査する。必須指定の移行（総務1の解除・副代表者1の必須化）と `forms_current_group_key` は「書込みを有効にする前に必要な設定」に表示する |
| 汎用同期のガード | ID22・ID21 も、同じアプリIDを別の app_key で登録した場合を含めて汎用の同期から操作できない |

追加テーブルはない（`002_roster_officer_sync.sql` は実行ステップを扱う次のPRで追加する）。

### 指示書から判断した点

- 公開フォームでは登録済みかどうかを返せないため、人物の申告は**枠に入れた全員に必須**とした。「情報不足」は、提出後に選択肢が変わった場合などの保険として比較画面に残している。
- 既存担当者を解除する差分は**担当者の比較画面**に表示する。公開フォームの確認画面は枠ごとの担当者と「空席」までを表示し、ID21 を読みに行かない。
- 定員超過は設計書のとおり担当者の確認に回すため、提出は止めず警告にした。

## 導入に必要な設定（比較プレビューまで）

kintone管理サイト「アプリ設定」に、次を同期ロール manual で登録する。APIトークンは**閲覧のみ**でよい。

| app_key | アプリ | 権限 |
| --- | --- | --- |
| `roster_people` | ID22 登録者 | レコード閲覧 |
| `roster_officers` | ID21 役員台帳 | レコード閲覧 |

`apps/config.php` の `roster.officers.write_enabled` は `false` のままにする（次のPRの書込みスイッチ。このPRには書込み処理がなく、値は画面の表示にだけ使う）。
