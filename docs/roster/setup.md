# 導入手順（部員名簿フォームと kintone 連携）

本番DBへの SQL 実行・kintone の本番アプリの更新（公開）は、この手順に沿って担当者が確認しながら行う。

## 1. DB（fitsc_forms）にテーブルを追加する

`apps/roster_core/migrations/001_roster_tables.sql` を fitsc_forms に実行する（phpMyAdmin の SQL 実行、または `mysql fitsc_forms < 001_roster_tables.sql`）。

- 追加するのは `roster_*` の10テーブルだけ。既存テーブルは変更しない。`CREATE TABLE IF NOT EXISTS` なので再実行しても既存データは消えない。
- `managed_forms` への外部キーがあるため、fitsc_forms で実行する。
- アプリも初回アクセス時に同じ定義でテーブルを作成するが（`roster_ensure_schema()`）、権限の都合で失敗しないよう、事前に SQL を実行しておくことを推奨する。
- fitsc_forms は既存のバックアップ対象（`backup_manager.db_targets`）に含まれているため、提出原本・accept・反映履歴もバックアップされる。

定義を変えたときは `php tools/roster_migration_sql.php > apps/roster_core/migrations/001_roster_tables.sql` で生成し直す（`--check` で一致を確認できる）。

## 2. 設定（apps/config.php）

`apps/config_up.php` の `roster` を参考に、`apps/config.php` へ追記する。APIトークンなどの資格情報は書かない。

```php
'roster' => [
    'enabled' => true,
    'kintone' => [
        'roster_app_key' => 'member_roster', // ID20 部員名簿
        'group_app_key' => 'groups',         // ID7 公認団体・組織
    ],
    'groups' => [
        'allowed_ranks' => ['部', '同好会', '愛好会', '組織'],
        'allowed_statuses' => ['活動中', '結成登録中'],
    ],
    'verification' => [
        'mail_transport' => 'smtp',          // 共通の SMTP 設定（smtp_host 等）で送信
        'mail_from_name' => '総合管理事務局 提出フォーム',
    ],
    'worker' => [
        'lock_file' => __DIR__ . '/kintone_core/storage/roster_worker.lock',
    ],
    'kintone_site_base_url' => 'https://（kintone管理サイトのURL）/',
],
```

省略した項目は `apps/roster_core/bootstrap.php` の `roster_default_config()` の値になる（フィールドコード、確認コードの有効期限15分・入力5回まで、団体確認の有効時間4時間、再試行の間隔など）。

## 3. kintone ID20 にフィールドを追加する

ID20「部員名簿」のテーブル `list`（部員名簿）の中に、次の3項目を追加する。いずれも**必須にしない・初期値なし**にする（状態が未設定の既存行があると、必須では更新できず、初期値があると未確認の値が確定してしまうため）。

| 表示名（例） | フィールドコード | 型 | 選択肢 | 初期値 | 必須 |
| --- | --- | --- | --- | --- | --- |
| 状態 | `membership_status` | ドロップダウン | 入部 / 在籍 / 卒部 / 退部 | 空欄（選択しない） | しない |
| 団体メール使用者 | `uses_group_email` | チェックボックス | 使用 | チェックなし | しない |
| HP更新担当者 | `is_website_editor` | チェックボックス | 担当 | チェックなし | しない |

手順:
1. kintone で ID20 を開き、アプリの設定 → フォーム。
2. テーブル「部員名簿」の右端に、ドロップダウン1つ・チェックボックス2つをドラッグする。
3. 各フィールドの設定で、フィールド名・フィールドコード（上表どおり）・選択肢・初期値・必須を設定する。チェックボックスは既定の選択肢（sample1 等）を削除して1つにする。
4. 「フォームを保存」→ 内容を確認してから「アプリを更新」（**本番の公開。実施前に関係者へ周知**）。
5. kintone管理サイト「反映・接続の確認」→「いま確認する」で「必要なフィールドと選択肢がそろっています」と出ることを確認する。

既存の項目について:
- `role`（役職）の選択肢 `- / 代表者 / 副代表者 / 会計長 / 副会計長 / 総務 / マネージャー` はそのまま使う。画面では Excel と同じ表記（部長・主将→代表者、副部長・副主将→副代表者、役職なし→`-`）で選ぶ。
- `role_name`（職名）は画面に出さず、既存の値を保持する。
- `phone_number` は文字列のまま（先頭の0を保持）。電話番号の必須範囲はフォームごとに設定できる（既定：役職のある在籍・入部の部員。マネージャーは切替で必須にできる）。kintone のフィールド設定は任意のまま。kintone 画面の案内文「役員は必須」とは、フォーム側の設定を「役職のある部員」にしておくことで整合する。
- ID20 の `group_id` には重複禁止がない。連携は `group_id` で検索して0件・1件・複数件を区別し、複数件なら担当者に競合として表示する（自動で統合・削除しない）。重複作成を DB 側でも防ぎたい場合は、別途 ID20 の `group_id` を「値の重複を禁止」にする移行を検討する（既存の重複レコードを整理してから設定する必要がある）。
- ID20 の通知（一般通知3件）は API による更新でも送られる（了承済み）。

## 4. APIトークンを発行し、kintone管理サイトに登録する

| app_key | アプリ | トークンの権限 | 用途 |
| --- | --- | --- | --- |
| `member_roster` | ID20 部員名簿 | レコード閲覧・追加・編集（削除は不要） | 名簿の検索・追加・更新、フィールドの確認 |
| `groups` | ID7 公認団体・組織 | レコード閲覧 | 団体一覧・団体メールの取得、ID20 のルックアップ（団体識別番号）の参照先 |

- ID20 へ新規登録するときはルックアップ（団体識別番号 → ID7）を使うため、2つのトークンを並べて送る（`X-Cybozu-API-Token: ID20のトークン,ID7のトークン`）。
- 各アプリの設定 → APIトークン → 生成 → 権限を設定して保存 →「アプリを更新」。
- kintone管理サイト「アプリ設定」（admin）で、app_key・表示名・サブドメイン・アプリID・**同期ロール manual**・トークンを登録する。トークンは暗号化して保存され、画面にも利用者向けの応答にも出ない。
- 部員名簿アプリ（`member_roster`）は、同期ロールに関係なく汎用の push/pull/再同期から操作できない。

## 5. 定期実行（cron）

XServer のサーバーパネル → Cron設定で、5分ごとに実行する（PHP 8.1 以上。パスは環境に合わせる）。

```
*/5 * * * * /usr/bin/php8.2 /home/（アカウント）/（ドメイン）/apps/jobs/roster_kintone_apply.php >> /home/（アカウント）/（ドメイン）/apps/kintone_core/storage/roster_worker_cron.log 2>&1
```

- 1回の実行で最大20件。ファイルロックで重複起動を防ぎ、ジョブは DB の期限付きロック（10分）で1件ずつ処理する。
- 団体一覧（ID7）は6時間ごとに自動更新する。すぐに更新したいときは「反映・接続の確認」→「いま更新する」、または `php apps/jobs/roster_kintone_apply.php --refresh-groups`。
- 稼働確認は kintone管理サイト「反映・接続の確認」の「反映ワーカー」（最終実行が30分以上前なら警告）。

## 6. 名簿フォームを作る（Forms 管理画面）

1. 新しいフォームを作り、基本設定の「部員名簿フォーム」で種類を「部員名簿フォーム」、対象年度（例：2026）、電話番号の必須範囲を設定して保存する。
2. 公開期間・配布資料・完了メッセージは通常のフォームと同じ設定が使える（日付入力・添付・追加項目は使わない）。
3. 新年度は対象年度を変更する（年度は日付から自動判定しない）。変更すると、前年度の未反映の accept は実行時に失効する。

## 7. 権限

| 操作 | 必要な権限 |
| --- | --- |
| 名簿の入力・提出 | 団体確認（ID7 の団体メールで受け取った確認コード） |
| 提出の閲覧（kintone管理サイト） | viewer 以上 |
| 差し戻し・accept・取り消し・再試行・今すぐ実行・団体一覧の更新 | operator 以上（サーバー側で確認） |
| アプリ設定（APIトークン登録） | admin |
